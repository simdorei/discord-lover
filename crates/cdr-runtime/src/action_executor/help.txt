Codex Discord Remote
연결된 디스코드 방에 일반 메시지를 보내면 그 방의 Codex 대화로 전달됩니다.
<값>은 필수, [값]은 생략 가능합니다. 꺾쇠·대괄호 자체는 입력하지 않습니다.
ref는 목록의 대화 ID(UUID) 또는 모호하지 않은 참조입니다. 안전하게 지정하려면 전체 ID를 복사하세요.
대상 우선순위: 명시한 ref → 현재 방 연결 → 방 연결이 없을 때 전역 선택. !where로 확인하세요.

대화
!new — 같은 방에서 내가 다음에 보낼 일반 메시지를 새 대화의 첫 요청으로 예약
!new <요청> — 현재 프로젝트에 새 Codex 대화와 새 디스코드 방을 만들고 첫 요청 실행
!list [개수] — 최근 목록, 기본 10/최대 30; 마지막·최대 입력과 누적 사용량 구분
!where — 이 방의 연결/전역 선택, 원본 ID·제목·폴더 확인
!status [ref] — 실제 서버 상태·목표·최근 user/final 기록; 조회 실패는 항목별 표시
!archive [ref] — 지정 대화 보관; 미처리 요청 등이 있으면 거절
!archived_list [개수] — 보관 목록, 기본 10/최대 50; 보관 시각 없는 경우 미확인
!resume [ref] — 원본 대화 연결 확인/불러오기; 이전 요청을 다시 보내지 않음
!open <ref> — 앱에서 지정 대화 열기: 구현·검증 미완료

작업 제어
!steer <추가 지시> — 진행 중인 원본 작업에 지시 추가
!stop [ref] — 해당 진행 작업에 중단 요청
!repair [ref] / !도구복구 [ref] — 유휴 채팅의 JS·Computer Use 도구 세션 초기화와 연결 확인; 앱 재시작·요청 취소 없음, JS 변수·핸들 초기화
!recover [ref] / !복구 [ref] — 해당 채팅 요청 취소 + 데스크톱 앱·봇·앱서버 재시작; 이전 요청 자동 재실행 없음(다른 앱 채팅도 중단, 다른 봇 작업도 중단)
!restart_codex — 작업·승인이 끝나면 Codex 앱서버 재시작
!restart_codex force / !force_restart — 진행 작업·승인·재시작 대기를 즉시 끊고 봇과 앱서버 강제 재시작
!retract [ref] — 이 방에서 내가 보낸 최신 대기 요청 취소; 실행 중 작업 중단과 다름
!runners — 실행·대기·검토가 필요한 저장 요청 확인
!runners <request_id> — 원래 작성자/방에서 원문 상세 조회; 재실행·복구 명령 아님
!discard-request <job_id> - 원 작성자·원래 방의 미시작 보류 요청 1건 폐기 확인; 자동 재실행·스레드 해제 없음
!approval — 기존 승인·입력 요청을 다시 표시

설정
!settings [ref] — 현재 설정과 저장된 설정의 출처 확인
!settings [ref] --model — 사용 가능한 모델 목록
!settings [ref] --effort — 추론 수준 목록
!settings [ref] --speed — 속도 선택지 목록
!settings [ref] --model <이름> --effort <수준> --speed <속도> — 지정한 항목만 변경
값에 공백이 있으면 따옴표로 묶습니다. --reasoning은 --effort와 같습니다.
모델 이름은 옵션 목록의 실제 값을 사용하세요. 모든 계정에서 같은 모델을 쓰는 것은 아닙니다.

사용량·최근 기록
!context — 현재 방의 마지막 기록 기준 입력량/최대 입력/한도/누적 사용량
!context all — 최근 여러 대화 조회; 읽기 한도와 미조회 수 표시
!context refresh [개수] — 파일을 다시 읽어 최근 기록 표시, 기본 10/최대 30
!usage [days] — 계정 사용량·한도, 기본 최근 7일/최대 30일
기록 시각과 조회 실패를 확인하세요. context는 현재 실시간 측정값이라는 뜻이 아닙니다.

점검·동기화
!mirror check [개수] — 연결 상태 조회만 수행, 방/매핑 변경 없음
!mirror list [개수] — 연결 목록 조회만 수행
!mirror sync — 대화 목록에 맞춰 디스코드 방/연결 갱신; 미처리 자료 보호
!bridge sync [개수] — 동기화 별칭, 개수 지정 시 최대 100
!doctor — DB·파일·Windows 주소 연결 등록 진단; 실제 앱 열기·화면은 미검증
!resources — CPU/RAM/디스크 실측, 단위·측정 구간·오류 표시
!pro <요청> — 현재 PC/프로젝트를 포함한 Pro 검토 요청
!interview <요청> — 구현 전에 요구사항을 질문하며 정리
!delete_archive <ref> — 보관 대화 삭제 미리보기; 안내된 별도 확인 필요
!help — 이 도움말

/ 명령
등록된 항목: /help /list /archived_list /status /settings /where /context /usage /new /interview /doctor /approval /runners /stop /retract /mirror_check /bridge_sync
/new·/interview는 prompt 필수. /settings는 ref/model/effort/speed, /context는 all_threads/refresh/limit 옵션입니다.
/list·/archived_list·/bridge_sync는 limit, /usage는 days, /status·/retract는 ref 옵션입니다.
! 명령 전용: archive, resume, open, steer, stop, resources, pro, delete_archive, 저장 요청 ID 상세 조회.
모델·추론 옵션 목록은 !settings의 값 없는 옵션으로 조회하세요. /ask·/use는 기존 호환 등록만 유지합니다.

별칭
archive_list=archived_list, setting=settings, map=where, ctx=context, recent=refresh(context 내부)
quota/limit=usage, queues=runners, system=resources, unqueue=retract
resync/sync/bridge sync=bridge_sync, approve=approval, deep_interview/deep-interview=interview
별칭은 ! 명령 기준입니다. 등록되지 않은 /별칭은 사용할 수 없습니다.

Reserve는 !settings --model gpt-reserve 로 수동 선택합니다. 자동 전환·자동 복귀는 하지 않습니다.
한도로 거절된 요청은 자동 재실행하지 않습니다. 모델 변경 후 새 요청을 보내세요. !runners에서 보류 상태를 확인할 수 있습니다.
